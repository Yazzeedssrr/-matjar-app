# MAKHRAJ admin safety release — 2026.09.20-safety2

## Scope

The existing `seller.html` URL now loads `makhraj-editor-v2.js` and `makhraj-seller-v3.js`. The older controller remains in the repository for reference. Existing account identifiers, Supabase project, product IDs, orders, stored photos, and Stripe keys are not replaced. No Stripe Live activation is included.

## Delivered

- Account-and-project-scoped local product drafts, using text metadata in localStorage and image Blobs in IndexedDB. Recovery is explicit. Browser data removal, private browsing, storage quotas, and eviction can remove these drafts. They are not cloud backups.
- Image preparation through the browser canvas: JPEG output with longest edge at most 1600px, at most 6 new images per request and 12 catalog images total. HEIC support depends on the browser's decoder; unsupported images show an actionable error.
- Admin-only `admin_save_product_v2` RPC: transactionally saves product, selected variant, costs, and image metadata. Uploaded image files precede the transaction and may remain unreferenced if saving fails; this release does not delete them automatically.
- Request receipts make unchanged retries idempotent. Optimistic timestamp checks reject stale product or stock edits. Missing purchase cost means preserve the saved cost, not delete it.
- Existing variant selection, category preservation, corrected inventory event handlers, and no duplicate manual inventory log insertion.
- Catalog JSON export containing product data, costs, categories, variants, and image URLs. It does NOT contain image binaries, customer accounts, orders, messages, or a one-click restore function. Exported costs are private; keep the file private.
- Sandbox orders excluded from real revenue. Overview figures cover the most recent 100 orders. Margin is an estimate from current recorded costs, not accounting net profit.
- Order progress editing no longer presents a misleading refund state as if it performed a financial refund. Payment refunds/cancellations still require their own workflow.
- Admin messages retain their original text. Translation is requested explicitly after a notice about sending message content to an external translation provider. Translation provider availability is not certified by this release.
- Scoped shell caching that does not clear localStorage, IndexedDB, Supabase records, or another application's caches. No forced reload while editing.

## Database verification actually performed

Assertions ran against the connected project inside a transaction that was fully rolled back. They verified admin-only access, draft creation and cost persistence, duplicate-request replay, changed-payload rejection, atomic rollback on a duplicate SKU, stale product and inventory rejection, publication validation, quantity validation, image-path validation, preservation of unrelated specifications, and preservation of an existing cost when omitted.

## Frontend verification actually performed

JavaScript syntax checks and 21 Chromium DOM/canvas assertions passed. Tests used locally controlled Supabase and storage doubles. Cases included empty inventory, sandbox revenue exclusion, actual 3200x1800 to 1600x900 canvas conversion, category preservation, draft text/Blob recovery with storage doubles, field preservation on direction changes, fractional stock rejection, retry identity, duplicate prevention, no repeat upload, blank-cost preservation, stale-stock warning, safe order status controls, empty support inbox, percentage validation, and export exclusions.

Browser navigation was blocked in the testing environment. Consequently, these are NOT end-to-end Safari tests and do not prove actual IndexedDB persistence on the user's iPhone, actual signed-in uploads, or CDN deployment. Those must be verified separately.

## Follow-up / known limits

- This is an admin reliability release, not a full storefront rewrite or complete multilingual localization.
- The legacy storefront controller still requires a regression pass, including category-tile handlers and the complete checkout flow.
- Full image-file backups and restore tooling are not implemented here.
- Translation uses the existing service; provider hardening and an actual conversation test are still needed.
- Real sales still require actual products, images, suitable fulfillment settings, and verified live payment configuration. No profits are promised.

## Rollback

Use Git history to restore the prior `seller.html` and shell assets if necessary. Do not delete or rebuild the database. The new RPC and receipt table are additive and can remain while the frontend is rolled back. Preserve any local drafts before clearing browser storage.
