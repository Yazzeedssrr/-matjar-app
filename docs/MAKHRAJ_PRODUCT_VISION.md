# مَخْرَج — Product Experience Blueprint

## الفكرة
مَخْرَج ليس قالب متجر. الهوية مبنية على الانتقال من العتمة إلى الوضوح: الخلفيات عميقة، الضوء الذهبي يحدد الإجراء المهم فقط، وكل شاشة تقلل التشويش بدل إضافة عناصر بلا وظيفة.

## مبادئ التجربة
1. الهاتف أولاً، واستخدام مريح بيد واحدة.
2. كل شاشة لها إجراء أساسي واحد واضح.
3. الصور والمنتج أهم من الزخرفة.
4. الحركة قصيرة وهادئة وتحترم prefers-reduced-motion.
5. الحالات الفارغة والتحميل والخطأ جزء من التصميم وليست أفكاراً لاحقة.
6. السلة والطلب لا يفقدان بياناتهما عند إغلاق التطبيق.
7. العربية RTL أصلية وليست ترجمة لواجهة إنجليزية.

## رحلة الزبون
Splash/نور → الرئيسية → اكتشاف/بحث → تفاصيل المنتج → اختيار الكمية → السلة → بيانات العميل → مراجعة الطلب → نجاح الطلب/رقم الطلب → تتبع الطلب.

## الرئيسية
- هوية مَخْرَج المصغرة.
- Hero موسمي قابل للتغيير من الإدارة.
- بحث فوري.
- تصنيفات أفقية.
- وصل حديثاً / مختارات / عروض.
- بطاقات منتجات مع صورة، السعر، حالة المخزون، المفضلة، إضافة سريعة.

## تفاصيل المنتج
- معرض صور قابل للسحب.
- اسم، سعر، وصف، مخزون.
- كمية +/-.
- زر ثابت أسفل الشاشة لإضافة المنتج.
- منتجات مرتبطة لاحقاً.

## السلة وCheckout
- تعديل الكمية والحذف.
- Subtotal + رسوم الشحن + الإجمالي.
- الاسم، الهاتف، العنوان، المدينة، ملاحظات.
- مراجعة أخيرة قبل الإرسال.
- شاشة نجاح هادئة بهوية الضوء ورقم طلب واضح.

## الطلبات
- البحث برقم الهاتف/رقم الطلب في النسخة الأولى.
- حالات: مستلم، قيد التجهيز، جاهز/تم الشحن، مكتمل، ملغى.
- Timeline بصري للحالة.

## الإدارة
لوحة منفصلة عن واجهة العميل: مؤشرات اليوم، الطلبات التي تحتاج إجراء، المخزون المنخفض، المنتجات، العملاء، الاستيراد، التقارير والإعدادات. لا يتم كشف وظائف الكتابة الإدارية للعميل.

## التقنية
النسخة القديمة مصدر بيانات/مرجع فقط. الواجهة الجديدة يجب أن تقرأ بيانات المنتج من طبقة API واضحة. الكتابة الحساسة تتطلب سياسات RLS/مصادقة مناسبة قبل Production. لا توضع أسرار إدارية في JavaScript أو Android.

## Android
بعد استقرار تدفق المتجر: package id نهائي، adaptive icon، splash، deep links، حالات offline، back navigation، signed AAB، privacy/data safety، ثم اختبار داخلي قبل Production.
